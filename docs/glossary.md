# Glossary

| Term | Meaning |
| --- | --- |
| AE | Account executive. Owns expansion and pricing; gets seat headroom as a task, never a CSM case |
| ARR | Annual recurring revenue: what the account pays per year |
| Automated | Handled by a campaign or left alone; no CSM time |
| Break/fix | A product fault. Support owns it; a pooled case stays open alongside |
| Band | The ARR range the pooled team covers. Below it is the automated tier; above it is a named CSM |
| Campaign | A sequence of automated emails and in-product messages for one situation, such as onboarding or a dormant account |
| Case | A unit of work for a pooled CSM, opened by a signal and closed with a close code |
| Customer ask | A request for help through the support queue. Support triages it; only advisory requests become pooled cases |
| Close code | How a case ended: saved, saved and right-sized, handed to the AE, handed up to a named CSM, lost with a reason, no reply, or back to campaign |
| CSM | Customer success manager |
| Dormant | Nobody active in the last 30 days |
| First touch | The first thing the CSM says or does on a case, written into the policy so every CSM starts the same way |
| GRR | Gross revenue retention: revenue kept at renewal, before any expansion. The team's main outcome measure |
| Hold | No outreach and no campaigns until the account's data is verified |
| Holdout | A random share of eligible accounts left to automation only, so the team's effect can be measured |
| Known friction | A question the docs or a campaign step already answers |
| Maturity level | How far an account has configured the product, L1 (defaults) to L4 (enforcing rules and reporting) |
| Named CSM | A CSM assigned to one account; accounts above the band have one |
| Pooled CS | A team that shares one queue of cases instead of owning a book of accounts |
| Renewal window | Calendar days until renewal. Monthly-term accounts are always inside it |
| Right-size | Reducing seats at renewal to what the account actually uses, to keep the customer |
| Seat headroom | More active users than seats purchased: a buying signal |
| Signal | A flag on an account that may open a case |
| SLA | Business days from a case opening to the first human touch |
| Solo | Exactly one active user |
| Stalled onboarding | In use by two or more people but still on default configuration after onboarding ends |
| True-up | Billing for users above the seats purchased |
